# DoOps 控制台 · 资源增删改查产品设计

2026 年 11 月 19 日 · 产品评审稿。适用入口为「资产 → 机器 → 虚拟机」及控制台顶部的「Kubernetes」「数据库」「网站」。[打开资源管理原型](resource-lifecycle-preview.html)

## 用户从哪里开始

值班人员想知道当前目标上运行着什么。负责发布的同事想改其中一个对象，并确认业务已经达到预期。两人均从独立列表页进入。虚拟机属于资产模块，平台实例由虚拟化来源定位。控制台各页的目标由顶栏选定，详情、变更预览、结果和审计记录始终带着同一个目标及对象标识。首页保留概览，资产台账负责登记和关联，集群、数据库和网站的实时操作留在各自标签内。

| 入口 | 当前工作区已支持 | 本方案拟补齐 |
|---|---|---|
| 虚拟机 | 机器台账、CSV 导入和宿主关系由资产模块另行交付 | 独立列表及详情。平台绑定后提供创建、开关机、改配、销毁，并单列移出台账 |
| Kubernetes | 查资源、日志和事件，扩缩容、滚动重启、节点调度、删除指定 Pod | 在工作负载详情完成创建、更新、删除及结果核验 |
| 数据库 | 从目标发现实例，查看发现信息，带入 DoSql 只读查询或生成变更计划 | 下钻实例内的真实逻辑库目录，按引擎提供受控变更。发现的实例、逻辑库、表内数据各有独立身份 |
| 网站 | 查看 DoWeb 发布记录，可发起巡检、发布、配置变更和回滚 | 在站点详情完成发布、更新、下线、恢复和删除，分别展示运行状态与发布历史 |

现状依据为当前工作区。线上版本须单独验收。[控制台说明](../../backend/docs/DOOPS_WEBUI.md) · [Kubernetes 操作清单](../../lib/k8s.ts) · [DoWeb 操作清单](../../backend/agent/internal/server/web_tool.go)

## 页面和操作流程

1. **列表。** 进入模块先显示资源表格。点击名称后进入有独立地址的详情页；列表不会自动选中第一行展示详情。详情页和浏览器的返回入口均恢复原筛选。页头显示当前目标和刷新时间。名称是详情入口。Kubernetes 按类型、命名空间和名称筛选，数据库按引擎、实例或库名筛选，网站按站点或域名筛选。「新建」带具体对象名，例如「新建工作负载」「新建逻辑库」「发布站点」。在数据库实例详情内才能选「新建逻辑库」。
2. **详情。** 顶部固定对象身份和状态，下方是配置、关联资源、最近操作。用户可直接点「扩缩容」「发布新版本」等常用动作。删除放在「更多」里，菜单项写明会删什么。需要自由描述的诊断或计划沿用现有 DoSql、DoWeb 表单。返回列表时恢复原筛选和位置。
3. **变更预览。** 同屏展示目标、对象、当前值、拟变更值、影响和回读方式。以「将副本数改为 3」「下线 portal」「删除逻辑库 orders」作为提交按钮。只读查看直接打开。若对象已被别人更新，提示重新读取，基于新状态再次预览。
4. **结果。** 提交后生成一条操作记录，显示执行中、已验证、失败、部分完成或结果待核实。只有核验完成才更新列表上的最终状态。断线后允许重新查看原操作；结果待核实时提供「核对结果」。返回详情可看到操作人、时间、变更内容及审计编号。

## 虚拟机的列表和详情

产品入口为 **资产 → 机器 → 虚拟机**。本次评审原型把四个入口并排，默认打开虚拟机列表。点「报表服务」进入 `vm-07` 详情。资产编号用来打开详情，管理地址或显示名称变更后仍指向同一条资产。

| 页面或动作 | 操作员看到的内容 | 完成依据 |
|---|---|---|
| 虚拟机列表 | 名称、资产编号、宿主、vCPU / 内存、管理地址、电源状态。支持按名称、编号、宿主、地址筛选。顶部提供「登记已有虚拟机」和「创建虚拟机」 | 选择名称打开独立详情；空列表保留新增入口 |
| 虚拟机详情 | 资产编号、平台来源与实例 ID、宿主、规格、管理地址、电源状态、Agent 接入状态及历史操作 | 平台实例和资产记录各有稳定身份。Agent 离线和 VM 关机分别呈现 |
| 登记已有虚拟机 | 填写资产信息及宿主，可稍后关联平台实例或 Agent | 台账可查。管理来源尚未绑定时显示「未验证」，可以继续编辑登记信息 |
| 创建虚拟机 | 选择有权操作的虚拟化平台、模板、宿主或资源池、计算规格、网络、磁盘策略 | 平台返回任务与实例 ID，回读成功后显示实际规格和电源状态。部分成功时保留两边标识以便核对 |
| 编辑台账、调整规格、开关机 | 台账编辑用于名称和管理地址。真实规格及电源交由已绑定平台执行。若平台要求离线改配，说明需停机及其服务影响 | 通过平台回读 CPU、内存、电源状态；客体服务可用性单列检查 |
| 移出台账 | 确认页显示资产编号与平台实例 ID，并说明平台实例继续运行或保持原电源状态 | 登记从活动列表移除，操作可查；可重新登记并关联同一平台实例 |
| 销毁实例 | 显示准确平台实例、依赖工作负载、关停影响和系统盘、数据盘、备份的处置。平台或磁盘策略不明确时不能提交 | 依据平台任务和实例查询核对结果，保留退役审计。原型假设独立数据盘保留，实际规则由平台确定 |

本设计沿用资产台账的角色约定，机器登记由平台管理员维护，普通用户按已有授权读取。供应平台连接和可操作范围属于后续实现决策。目标 Agent 的授权不能替代虚拟化平台授权。原型采用单一演示平台和宿主数据，不预设真实云厂商或私有化平台。[宿主访问边界](../../backend/docs/PHYSICAL_HOST_ACCESS.md)

## 按资源定义增删改查

下表是拟议产品范围。每一个可提交的动作都须有服务端支持、目标侧执行和可读取的结果。尚未支持的动作可以在能力说明里解释，不能提交后才假装成功。

| 实际对象 | 新增 | 查看 | 修改 | 删除及影响 |
|---|---|---|---|---|
| K8s Deployment | 选择命名空间，填名称、镜像、副本数等发布参数，预览后创建 | 期望与就绪副本、镜像、关联 Pod、事件、发布来源 | 扩缩容、换镜像、滚动重启。GitOps 管理的对象沿已有发布来源更新 | 「删除工作负载」预览控制器及其管理的副本。关联 Service、PVC 分别展示处理结果；清理存储须独立授权并另行设计 |
| K8s Pod、节点与命名空间 | Pod 优先从所属工作负载创建。节点接入和新建命名空间各有自己的生命周期 | 看 Pod 日志及控制器、节点状态与容量、命名空间范围 | 对受管 Pod 的持久配置引导至所属工作负载。节点提供停止和恢复调度 | 「删除 Pod」提示控制器可能补建新 Pod，并区分旧 UID 与新 UID。首版不开放节点移除及命名空间级联删除 |
| 由平台供应的数据库实例（扩展评审） | 选择支持的供应来源、引擎和容量 | 查实例身份、实际容量与库目录 | 预览容量调整，回读供应平台规格 | 「销毁数据库实例」列出内含逻辑库和备份恢复依据。原型模拟 PostgreSQL 供应方。交付依赖真实供应接口与授权 |
| 已发现数据库实例 | 「重新发现」读取目标候选。已有实例可使用绑定凭据进入库目录 | 显示实例来源、引擎、连接验证时间及真实库目录。识别到实例与连接成功分别显示 | 查看与维护已有凭据绑定沿用凭据入口 | 销毁实例涉及部署来源、数据卷和备份。须单独确定实例供应方式及交付范围 |
| 实例内的逻辑库 | 在指定实例创建逻辑库，显式选择引擎支持的名称及参数 | 展开库目录、结构，在选定库内运行只读查询 | 提交该引擎支持的结构变更，如新增列。展示计划、影响和验证；结构或数据变更走受控 DoOps / DoSql | 「删除逻辑库」列出实例、精确库名、已知依赖和可用恢复依据。执行后重新读目录。若执行器无法覆盖该引擎的管理连接、权限或恢复要求，显示具体原因 |
| DoWeb 站点 | 指定目标、运行方式、站点 ID、域名、已构建产物和健康检查地址，发布首版 | 域名、活动版本、上一版本、最近一次健康检查及时间。已发布和在线健康分别展示 | 发布新版本、更新配置、回滚到指定可恢复版本 | 「下线」停用站点路由并保留版本，可重新上线。「删除站点」清理明确属于该站点的配置和版本；预览列出清理对象与恢复条件。域名注册、DNS、共享证书与审计记录另有归属 |

**交付顺序建议。** 虚拟机先交付台账列表与详情，再接入选定平台验证电源、改配及完整供应生命周期。应用侧先交付 Deployment 和 DoWeb 站点两个完整闭环。数据库首个验证对象建议为已纳管 PostgreSQL 实例中的逻辑库；先验证独立管理连接、精确凭据范围、建库/删库与结构回读，再逐引擎开放。具备事务的操作展示提交结果，部分已提交的 DDL 记录已执行步骤和恢复入口。[数据库执行与确认结果](../../backend/docs/DOOPS_USAGE_GUIDE.md)

## 三个典型场景

**工作负载扩容。** 用户进入 `test / k8s-agent → apps → Deployment/api`，看见期望 2、就绪 2。将副本改为 3 后，预览显示 `2 → 3`。提交后先显示「已接受，等待就绪」，直到当前发布修订显示 3 个就绪副本才记为已验证。若调度失败，将对应事件放在这条操作记录下。

**在已有实例创建逻辑库。** 用户从 `orders-postgres` 进入库目录，选择「新建逻辑库」，输入 `orders_archive`。预览列出目标、实例、引擎、绑定凭据引用和拟新增的库名。提交前核对同名库；提交后用同一实例的管理连接回读目录。库已存在时保留原库并提示重名。若仅有业务库的查询权限，返回具体缺失权限并提供已有凭据入口。

**站点下线后恢复。** 用户选中 `portal.example.test`，在详情看到当前版本与正在使用的路由。点「下线站点」后，预览写明该域名将停止由此站点提供服务，保留可恢复版本。提交后验证配置已生效、此域名已退出该站点路由、同目标的其他站点仍可用。详情提供「重新上线」。若域名后来被其他站点占用，恢复时展示冲突对象，保持当前状态。

## 权限、失败状态与验收

Gateway 延用当前用户与目标的授权，Kubernetes RBAC、数据库凭据和目标运行条件决定具体操作能否执行。管理员管理接入、目标授权和凭据绑定。获得目标授权的操作员可以在其可执行范围内完成动作，产品不引入独立的逐按钮角色体系。页面的可用性提示用于解释条件，服务端在提交时核对实际权限。所有 SQL 变更沿受控数据库执行链路留痕。[仓库开发契约](../../AGENTS.md) · [DoWeb 执行约定](../../backend/docs/DOWEB_INTEGRATION.md)

| 场景 | 浏览器和目标侧必须观察到的结果 |
|---|---|
| 首次加载、无结果、无权限、目标离线 | 四种状态有独立文案。只在成功读到空集合时显示「暂无资源」。权限部分缺失时，可读类别仍可使用 |
| 切换目标后打开同名资源 | 清除上一个目标的选中项和未提交表单；面包屑、预览和实际请求均指向新目标 |
| 两人编辑同一对象或连续点两次提交 | 陈旧预览提示重新核对。重复点击只生成一次变更，页面可重新进入同一条操作记录 |
| Deployment 从 2 扩到 3 | 提交、配置生效、3 个副本就绪可以区分；就绪失败有目标侧证据 |
| 新建逻辑库成功、重名或被拒 | 成功有目录回读记录。重名和权限不足保留具体原因；列表里不会出现未创建的库 |
| 网站下线及恢复 | 站点详情能重新上线；域名的路由和健康状态与操作回执一致。同目标另一个站点通过验收 |
| 删除响应中途断开 | 显示「结果待核实」和原操作编号。重新进入后核对目标对象身份及状态，再决定是否继续。审计在对象消失后仍可查 |

## 本轮评审决定

1. **虚拟化平台的首个接入对象。** 评审后确认首个平台、实例身份来源、授权、是否支持热改配及磁盘回收策略。
2. **数据库的交付对象。** 建议先交付“已有实例里的逻辑库与结构”。如果需要用户新建或销毁 PostgreSQL/MySQL 服务实例，另行设计实例来源、规格、持久卷、备份恢复和删除后果。这一选择会改变排期和后端范围。
3. **网站删除的交付顺序。** 建议先验收可恢复下线，再开放永久清理；永久清理的版本留存期限及恢复依据由业务确认。
4. **首批 Kubernetes 对象。** 建议选择 Deployment 走通完整生命周期；Pod、节点和命名空间按上表提供合适动作。后续按同一验收标准扩展 StatefulSet 和 Service。

## 原型验收范围

四类资源均有独立列表、搜索、新增、详情、编辑、删除预览和操作记录。虚拟机可验证登记、创建、关联、电源和改配，能分别走通移出台账和销毁；Deployment 可创建、改镜像与副本并删除；数据库实例可模拟创建、扩容和销毁，实例内的逻辑库可创建、查看、调整连接上限和删除；网站可发布、修改版本与域名、下线、恢复和删除。删除后返回列表，最近操作仍可查询。所有写入局限于本页内存，刷新重置。真实供应、权限拒绝、并发冲突和执行失败恢复以正式产品验收为准。
