## 机器手工录入与 CSV（待实现）

手工表单和 UTF-8 CSV 共用下表。CSV 首行为列名，选填值可留空。以下示例登记一台物理机和一台 VM，容量均为登记时的配置值。

| CSV 列 | 表单字段 | 规则 |
| --- | --- | --- |
| `asset_id` | 资产编号 | 必填；台账内稳定唯一，按编号识别重复。改名或更换 IP 后仍沿用原编号。 |
| `name` | 显示名称 | 必填；允许重名。 |
| `kind` | 类型 | 必填；`physical` 物理机、`vm` 虚拟机。 |
| `address` | 管理地址 | 选填；IP 或主机名，仅作登记。 |
| `cpu_count` | CPU 数 | 选填正整数；物理机填物理核心数，VM 填分配的 vCPU 数。 |
| `memory_gib` | 内存（GiB） | 选填正数；物理机填安装容量，VM 填分配容量。 |
| `disk_gib` | 磁盘（GiB） | 选填正数；物理机填本机磁盘总容量，VM 填虚拟磁盘配置总量。未知容量显示「未登记」。 |
| `host_asset_id` | 宿主资产编号 | VM 可选；引用已登记或本批次内有效的物理机。引用与行顺序无关。物理机填此列、自引用、引用 VM 或找不到宿主均报行错误。 |

手工示例：选择「虚拟机」，填编号 `vm-07`、名称 `报表服务`、CPU `4`、内存 `16`、磁盘 `120`，在宿主选择器中选 `phy-01`。保存后，VM 详情链接到宿主，宿主详情列出 `vm-07`；宿主容量单独展示，避免把 VM 容量重复计入物理总量。

```csv
asset_id,name,kind,address,cpu_count,memory_gib,disk_gib,host_asset_id
phy-01,一号宿主,physical,192.0.2.10,32,256,2048,
vm-07,报表服务,vm,192.0.2.17,4,16,120,phy-01
```

### 批次预览、确认与重试

1. 上传后先预览，总数按「可新增／重复跳过／行错误」三项核对。表头缺失必填列、未知列或 CSV 无法解析时，整批退回并指出原因。预览和取消均不写入台账。
2. 对同一编号，内容相同的批内后续行或库内记录标为重复；内容冲突的批内各行、与库内记录冲突的输入行均报错。结果列出 CSV 行号（表头为第 1 行）、列名、原因和修正建议。同名或同 IP 不触发合并。
3. 用户确认「仅导入可新增的 N 行」后，服务端复核权限、重复和宿主关系。若宿主落库失败，依赖它的 VM 也返回行错误。结果按行显示新增、跳过或失败，附批次号。并发导入或重复确认不能覆盖已有资产。
4. 确认响应中断时，重新打开原批次查询结果。对失败行修正后重新预览，只重试这些行，保留原批次号、原行号与尝试记录。已成功的行可作为宿主引用，不重复创建。

## 通过已授权 Agent 发现 K8s（待实现）

用户选择已授权的在线目标，核对 `cluster/instance` 后发起只读发现。首个入口由管理员新建集群资产编号，或者选择已有集群。新增入口指向同一集群时，保留一条集群资产和多条访问来源。仅凭路由名、IP 或集群显示名相同，不能自动合并。每次发现记录来源目标、观察时间和实际可读范围。Gateway 检查目标授权，Kubernetes API 按 Agent 的实际 RBAC 返回数据。

导入页面提供「整个集群」和「指定命名空间」。后者允许手填名称，也允许从成功读取的列表勾选。预览逐项展示来源、集群编号、命名空间、读取结果和本次新增或更新数。保存后可从集群详情打开已纳管的命名空间列表。相同集群中重复提交同一命名空间更新观察时间；不同集群中的同名空间各保留一条。能读取 Namespace 对象时保存 UID，UID 变化提示对象已重建。权限仅支持读取工作负载时，列表标出验证范围。移除纳管关系只修改台账。

对于可读的 Node，记录集群、Node UID、名称和最近观测。云平台实例标识与 VM 已登记的标识精确一致时可以建立关系。缺少标识或出现多匹配时展示「待关联」，由管理者从已登记机器中确认。点开 VM 可反查集群和 Node；首次接入或断联都不改变机器数量。

能列举 Namespace 时展示返回的名称；选择某个命名空间后，再执行具体的只读资源请求。若 Agent 仅持有 `reports` 的 Role，集群级命名空间枚举返回 Forbidden 时显示「无权列举命名空间」，允许填写已知名称。以授予 `list pods` 的 Role 为例，定向读取 `reports` 的 Pods，成功即记录「已验证 reports 可列举 Pods」，空列表同样有效。若该 Role 只授权其他资源，则以其实际获准的资源和读操作验证并标明范围。拒绝、超时、Agent 离线分别展示；不把单项读取成功推断为其他命名空间可读或可写。

## 凭据复用、权限与审计（拟接入现有能力）

- 台账录入不接受密码、私钥、token 或 kubeconfig。关联现有 Agent 须显式选定已授权目标；录入管理地址或宿主关系不会创建目标授权。初版建议由平台管理员维护未接入台账；普通操作员只看自己获授权目标关联的记录，宿主或 VM 链接也按读者权限过滤。
- 「我管理的」按既有归属管理个人或平台资源。管理者选择凭据、绑定目标并提交 staged 版本验证；所有有效绑定均验证通过后才可激活。轮换创建新版本，失败时保留原 active 版本。吊销某个绑定只影响该目标；吊销整个资源覆盖其所有绑定，清理结果沿用既有凭据流程。
- 「当前目标可用」只列已绑定该目标的有效资源及 active 版本。目标操作员可按绑定使用，管理动作仍检查归属。任何列表、详情、导入批次和重试请求均由服务端重新检查身份与访问范围，撤权后停止展示先前缓存的记录。
- 审计记录操作者、时间、批次或操作标识、资产编号或目标、动作、结果与失败原因。发现记录命名空间和实际验证的资源范围；凭据操作关联资源、版本和绑定标识。日志和错误仅保留必要元数据，排除原始上传内容和秘密值。

## 功能验收用例（待实现后执行）

含账号密码的源表应从转换前记录验收范围。整表成功需要按源行核对资产、账号和受管凭据的持久化关联，用合成凭据回读验证，公开回执只记录状态和数量。多个账号分别核对，属于其他机器的凭据不能抵数。原文件缺失时应记录期望数量未知。台账模式只验收资产字段。含凭据模式还要检验已有资产补录、新机器与凭据同时保存、重复账号、冲突、未授权账号可见性，以及重启后机器与凭据的关联。见[使用说明](../../backend/docs/DOOPS_WEBUI.md#资产台账)。

| 场景 | 操作 | 可观察结果 |
| --- | --- | --- |
| 手工与 CSV 等价 | 在两份空台账中，分别手工登记示例两台机器、上传示例 CSV（交换两行顺序）。 | 两份台账均有两条记录，类型、容量与双向宿主链接一致；无 Agent 时均显示未接入。 |
| 批次可取消、可部分成功 | 在空库给示例追加相同的 `vm-07` 和一个内存为 `-1` 的新编号。预览后取消，再上传确认。 | 首次取消后零新增；再次预览共 4 行，可新增 2、重复 1、错误 1。确认后新增 2 台，错误指向第 5 行 `memory_gib`。 |
| 修正与重放 | 修正上例失败行并重试；模拟确认响应丢失，刷新批次并再次确认。 | 最终共 3 台；批次可追溯失败行、修正和最终结果。 |
| 编号冲突与宿主错误 | 修改已有编号的 CPU 再导入；另试不存在的宿主、VM 作宿主，以及两人并发导入同一新编号。 | 冲突显示字段差异，原容量保留；无效宿主均指向 `host_asset_id`；并发确认后该编号仅一条。 |
| 集群发现与单 ns Role | 分别以可列 Namespace 的 Agent 和仅可在 `reports` 列 Pods 的 Agent 发现。后者依次验证空的 `reports`、未授权的 `other`。 | 前者列出授权返回的名称；后者保留枚举拒绝，`reports` 显示验证成功且 0 个 Pod，`other` 显示拒绝。未申请集群级权限。 |
| 三入口离线 | 已登记机器、发现集群并绑定有效凭据后断开 Agent，依次进入机器、集群、凭据列表，再恢复连接并刷新。 | 机器保留容量，集群保留带时间的历史记录，凭据保留可见元数据；离线期间不能执行远程操作或记为验证成功。重连后可重新取得实时结果。 |
| 绑定、验证与轮换 | 同一凭据绑定 A/B，令新版本在 B 验证失败后尝试激活；修复并复验后再激活。 | 首次激活被拒，A/B 仍使用旧版本；全部有效绑定验证通过后，两个目标均可使用新版本。 |
| 吊销与归属 | 管理者先吊销 A 绑定，再吊销资源。仅有 B 授权的非所有者分别打开两个视图并尝试管理。 | 第一次吊销后 B 仍可用，第二次后 B 也不可用；操作员始终无法管理他人的个人凭据，目标视图不返回秘密值。 |
| 越权与审计 | 撤销目标授权后刷新详情、重放发现请求；普通操作员尝试确认管理员的批次；管理员按批次和目标核查成功、失败及重试记录。 | 服务端拒绝越权请求且无写入，页面不泄露资产名或宿主信息。审计能还原操作者、范围和结果，错误回执与审计均不含秘密值。 |
